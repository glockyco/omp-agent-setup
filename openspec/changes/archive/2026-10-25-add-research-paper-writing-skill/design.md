## Context

The personal plugin packages `plugin/` as a self-contained OMP directory. Its `plugin/skills/` contains authored personal skills alongside generated OpenSpec skills. The latter are regenerated by a separate command and must not be edited. `plugin/tests/plugin-load.test.ts` enumerates the selected authored skills. The workstation loads a pinned plugin output and owns activation. See `proposal.md` for motivation and `specs/research-paper-writing/spec.md` for the new behavior.

The upstream MIT-licensed Research Paper Writing Skills repository has one `research-paper-writing/SKILL.md`, section guides and examples under `references/`, and `agents/openai.yaml` metadata. Its method-paper examples and persuasive framing are part of the selected package. A rewrite is not required to make them useful in other disciplines.

## Goals / Non-Goals

**Goals:**

- Reproduce one identifiable upstream revision as a self-contained authored skill in the immutable plugin.
- Preserve the full upstream writing workflow, section guides, examples, and metadata while retaining source attribution and license terms.
- Establish a release check that detects missing support files and proves discovery in a real wrapped OMP session.

**Non-Goals:**

- Install a second writing or AI4SE reporting skill, fork the writing method, or impose an SE-specific template.
- Add a download path, scheduler, global user-state write, or new OMP extension.
- Publish the plugin, update the workstation pin, or activate a host as part of this proposal.

## Decisions

1. **Vendor a fixed upstream snapshot under `plugin/skills/research-paper-writing/`.** Copy the complete skill directory and retain its relative links. Record the repository and exact commit in this change. Include the upstream copyright and MIT license notice in the package. This is preferable to a runtime fetch or an unpinned dependency: OMP can read the same guidance from a Nix store path on every host. Do not install it in a paper repository or edit the generated OpenSpec adapters.

2. **Keep the skill's writing guidance unchanged.** Its `SKILL.md` selects section guides as needed, so the package need not load the full example bank into every conversation. Do not add universal paper-type rules or soften its advice about making the strongest honest case. The existing `research-evidence` skill remains the source-reading and metadata workflow. A claim-evidence map from the writing skill does not certify cited claims.

3. **Test the packaged boundary, then the actual interface.** Update the existing authored-skill inventory assertion in `plugin/tests/plugin-load.test.ts` and the flake's package-shape check to require the entry point and representative linked references in the built output. Exercise the loaded skill in a fresh wrapped OMP session with a small, non-confidential paper-writing scenario: request a section outline and consult a linked section guide. This checks real discovery rather than only file presence. Keep the existing CI and flake release gates.

4. **Record the third-party rights exception.** Upstream's MIT license permits redistribution of its author's work with the notice. It does not establish rights in material from other sources. The user chose to include the complete upstream snapshot despite unresolved redistribution permission for the college handout and adapted research notes. Keep the source review and unresolved status in this change. Do not claim that the MIT license covers those sources.

## Source review

The selected upstream revision is [`77e7c2c1ba06f7d71844873147665437a03aac1b`](https://github.com/Master-cai/Research-Paper-Writing-Skills/commit/77e7c2c1ba06f7d71844873147665437a03aac1b). Its `research-paper-writing/` tree contains 39 tracked files. All 114 relative Markdown file references checked against that tree resolve. The upstream [MIT license](https://github.com/Master-cai/Research-Paper-Writing-Skills/blob/77e7c2c1ba06f7d71844873147665437a03aac1b/LICENSE) permits redistribution of its author's work if the notice remains with the package.

Redistribution rights for all source material are **not yet established**. The upstream [README](https://github.com/Master-cai/Research-Paper-Writing-Skills/blob/77e7c2c1ba06f7d71844873147665437a03aac1b/README.md) attributes much of its guidance to [Peng Sida's notes](https://github.com/pengsida/learning_research), which have no repository license. Their README asks for source credit when reposted. The complete text in `references/does-my-writing-flow-source.md` matches the [San Antonio College Writing Center handout](https://www.alamo.edu/siteassets/sac/about-sac/college-offices/writing-center/does-my-writing-flow.pdf). That handout has no redistribution license, and the college's [copyright guidance](https://www.alamo.edu/about-us/offices-departments/departments/legal-services/) does not grant one. The user explicitly directed inclusion of the full package despite this unresolved risk. This is a scope decision, not proof of redistribution permission.

## Risks / Trade-offs

- [Upstream changes after vendoring] -> Record a commit and content provenance so updates are reviewed, not silently adopted.
- [Long example bank increases payload size] -> Ship it intact but rely on the skill's selective reference loading. Measure the package and confirm discovery, rather than editing examples speculatively.
- [Third-party permission remains unverified] -> Preserve source attribution and the explicit risk record. Inclusion at the user's direction does not grant rights.
- [Host-specific `agents/openai.yaml` may not be used by OMP] -> Keep it as inert upstream package metadata, not a top-level `plugin/agents/` registration. Verify OMP still loads one skill and no new agent.

## Verification evidence

The 39 upstream skill files matched commit `77e7c2c1ba06f7d71844873147665437a03aac1b` byte for byte. The package adds only the upstream `LICENSE` file. Strict OpenSpec validation passed. `nix develop --command bun run ci` passed with 28 tests. `nix flake check` passed after the new files were added to Git's source index.

A fresh noninteractive OMP session used the installed wrapper's commands with both plugin paths changed to the locally built output at `/nix/store/qlzbcb6bhkc681fyy198pv31kx3a1m80-personal-omp-plugin-0.1.0`. The session returned a four-part introduction outline for a sample static-analysis paper. It reported reading `skill://research-paper-writing` and `skill://research-paper-writing/references/introduction.md`, and reported that `research-evidence` remained discoverable. It made no repository edits or citation claims. This smoke did not publish or activate the candidate plugin.

## Migration Plan

No existing skill name or workflow is replaced. Implementation and verification occur in `omp-agent-setup`. Exposing a published revision on the workstation requires a separately authorized plugin-pin update, build, activation, and wrapped-session smoke under the workstation's release procedure. A failed rollout retains the previous pinned plugin generation. No mutable manuscript state is migrated.
