# Documentation Audit — 2026-05-16

Audit of `README.md`, `AGENTS.md`, `agent/AGENTS.md`, and the 4 managed `agent/skills/<name>/SKILL.md` files against `skill://writing-project-readmes`, `skill://writing-agent-instructions`, and `skill://writing-omp-skills`.

Findings categorised:

- **C** = Critical — factual incorrectness or stale claim that misleads
- **I** = Important — skill-rule violation that hurts the document's job
- **M** = Minor — polish, redundancy, style nit

For each: file + line, what's wrong, what the skill says, recommended fix.

## `README.md` (121 lines) — `skill://writing-project-readmes`

### Strengths

- Opens with purpose + audience scope ("personal global setup … treat as a dotfile, not a packaged tool"). Within the first screen, the reader knows what this is, why it exists, and that it isn't a reusable library. ✓ skill: "what the project is, why it exists, and how to start within the first screen."
- Quickstart is verified, source-backed commands (lines 35–40). ✓ skill: "Prefer source-backed commands."
- Tables for deployment surfaces and scripts are concise. ✓ skill content model.
- Links to `AGENTS.md` at the end instead of inlining agent-only operations. ✓ skill: "Keep README human-facing. Link to agent instructions."

### Issues

#### C1 — "What it does" bullets are stale (omit Zed)

- **File:** `README.md:11-16`
- **Wrong:** The 5-bullet list of what bootstrap does was written before the Zed-settings managed surface landed. It mentions config.yml, plugin forks, patches, and verify — but does not mention `~/.config/zed/settings.json`. The table 30 lines below (the "What gets deployed" table) is current. The two now disagree.
- **Skill:** "Verify every referenced file or directory exists." More broadly, content correctness.
- **Fix options:**
  1. Add a 6th bullet for Zed settings.
  2. Delete the bullet list entirely. The table that follows says the same thing and is the source of truth for "what gets deployed." This is also the cleaner option per the skill's "Remove placeholders, stale output, and generic boilerplate." Recommended.

#### C2 — "What gets deployed" row for `config.yml` cites the wrong source

- **File:** `README.md:52`
- **Wrong:** Row reads `| managed keys in config/config.yml.template | ~/.omp/agent/config.yml | merged YAML, unrelated keys preserved |`. The actual managed-key source is `src/config.ts` (`MANAGED_CONFIG`), which `mergeManagedConfig` consumes. `config/config.yml.template` is a separate reference template that bootstrap does not read. The Zed row two lines below correctly cites `src/zed-settings.ts` — the pattern is set, this row is the outlier.
- **Skill:** "Prefer source-backed commands"; correctness.
- **Fix:** Change `config/config.yml.template` → `src/config.ts` (`MANAGED_CONFIG`).

#### I3 — "LSP" section is too long for a human README

- **File:** `README.md:68-77` (and especially the runaway 4-sentence paragraph at line 77)
- **Wrong:** ~250 words on the three-layer LSP design, audit divergences from OMP's `loadConfig`, parse-failure degradation behaviour, sub-package enumeration heuristics. This is architecture trivia an agent or maintainer needs, not a human evaluating whether to copy the repo.
- **Skill:** "Architecture / layout: Only orientation facts that help humans" and "Link to source-of-truth docs instead of duplicating them." This duplicates and exceeds `AGENTS.md`'s LSP-maintenance section.
- **Fix:** Trim to a 3-sentence orientation paragraph: what `bun run audit-lsp` does, where the three layers live (`scripts/install-lsp.sh`, `agent/lsp.json`, repo-local last resort), link to `AGENTS.md` for the layered policy. Move the audit-edge-cases sentence to `AGENTS.md` or delete it (it's already there).

#### I4 — "Zed integration" overlaps with `AGENTS.md`

- **File:** `README.md:79-86`
- **Wrong:** 4 paragraphs of Zed integration rationale, most of which is mirrored in `AGENTS.md:71-77`. The README copy includes implementation detail ("via `jsonc-parser`", `omp acp` subcommand, ACP RPC method names) that human readers don't need.
- **Skill:** "Keep README human-facing. Link to agent instructions instead of copying agent-only boundaries or tool constraints."
- **Fix:** Reduce to ~3 sentences: "Bootstrap registers OMP as a custom ACP agent in Zed's `agent_servers`. C# LSP is intentionally split — Zed → Roslyn, OMP → csharp-ls. Architecture and trade-offs: see `AGENTS.md`." Drop the Razor/CSHTML mini-treatise (it's already in AGENTS).

#### M5 — Zed deployed-table cell mentions implementation detail

- **File:** `README.md:54`
- **Wrong:** Row reads `| managed keys in src/zed-settings.ts | ~/.config/zed/settings.json | merged JSONC (via jsonc-parser), unrelated keys and comments preserved; managed entry uses absolute omp path resolved at bootstrap time |`. The third column is doing too much. "via jsonc-parser" and "absolute omp path resolved at bootstrap time" are implementation notes a maintainer can read from AGENTS.md or the source.
- **Fix:** `| merged JSONC, unrelated keys and comments preserved |` — matches the cadence of the other rows.

#### M6 — Quickstart includes `bun run verify` which runs the live acceptance smoke

- **File:** `README.md:39`
- **Wrong:** Skill says "Do not run setup, bootstrap, install, deploy, migration, credentialed, expensive, networked, external-service, or write-config commands just to verify docs." That's about *docs verification*, not the Quickstart itself, so this is not a strict violation. But the user copying this on a fresh machine will hit `verify`'s model-heavy acceptance smoke (~$$ + slow) without knowing it. Currently the only signal is `OMP_VERIFY_SKIP_ACCEPTANCE=1` mentioned in the commands table, never in the Quickstart.
- **Fix:** Either drop `bun run verify` from the Quickstart (recommend skipping by default; the doctor + first real-use is the smoke) OR add `OMP_VERIFY_SKIP_ACCEPTANCE=1 bun run verify` to the Quickstart and link to the full gate in the commands table.

## `AGENTS.md` (root, 93 lines) — `skill://writing-agent-instructions`

### Strengths

- Under the 100-line target. ✓
- Commands table near the top. ✓ skill: "Put commands early."
- 9-row `Don't / Instead` boundary table. High-signal, exactly the format the skill prescribes.
- Architecture paragraph cites a concrete example (`executeCheckoutSteps(steps, runner, probe)`). ✓ skill: "Use concrete, verifiable statements over generic advice."
- Links to `skill://commit` instead of inlining. ✓

### Issues

#### I7 — "Code style" restates formatter coverage

- **File:** `AGENTS.md:27-29`
- **Wrong:** `TypeScript strict. Biome enforces format and lint, and bun run fix rewrites.`
- **Skill:** Explicit: "Do not restate formatter, linter, or typechecker settings unless agents repeatedly violate them despite tooling." Biome runs in lefthook + CI; we have no RED evidence of repeated agent violation.
- **Fix:** Delete the section. If we want a "Style" anchor for future repo-specific pitfalls, replace the body with a stub: `No repo-specific style rules beyond what Biome enforces.`

#### I8 — "Commits" section restates lefthook configuration

- **File:** `AGENTS.md:35-37`
- **Wrong:** "Lefthook runs Biome + `tsc` on staged files at `pre-commit` and `bun install --frozen-lockfile && bun run ci` at `pre-push`. GitHub merge mode is rebase-only with auto-branch-delete."
- **Skill:** Same rule — don't restate enforcement that tooling guarantees. The hooks fire whether or not AGENTS.md says so.
- **Fix:** Reduce to one line: `Use Conventional Commits (skill://commit). Lefthook enforces lint + typecheck at pre-commit and the full CI gate at pre-push.`

#### I9 — "Plugin update" section duplicates a boundary row

- **File:** `AGENTS.md:79` vs `AGENTS.md:45`
- **Wrong:** Both say the same flow: `bun run update-<plugin>` → `verify` → push `omp-local` → bump `currentCommit`.
- **Skill:** "Move multi-step workflows into skills or docs and reference them." And avoid duplication.
- **Fix:** Drop the standalone section; keep the boundary row (it's the more useful framing — "don't bypass the manifest, do this instead").

#### I10 — "OMP update" section partially overlaps a boundary row

- **File:** `AGENTS.md:83-85` vs `AGENTS.md:48`
- **Wrong:** Boundary row covers the policy ("add to `src/patches.ts`"); section covers the *recovery* ("if `skip-anchor-missing`, fix the patch"). The overlap is in declaring that `omp update` clobbers patches.
- **Fix:** Keep the section (the recovery detail is valuable) but trim the first sentence — it's restating what the boundary already says. Lead with: `If bootstrap reports skip-anchor-missing for a patch, OMP rewrote the surrounding code — update the patch's anchor/replacement in src/patches.ts to match the new shape.`

#### I11 — "Zed integration" section is too long for AGENTS.md

- **File:** `AGENTS.md:71-77`
- **Wrong:** 5 paragraphs (jsonc-parser internals, Bun.which rationale, C# split rationale, OmniSharp contingency, extension-of-managed-keys instructions). The skill says: "Architecture: Facts agents cannot infer cheaply." Most of this is human-facing rationale, not agent-operational.
- **Fix:** Keep:
  - The boundary row at line 50 (which is already correct).
  - A 3-sentence operational summary: where the source lives (`src/zed-settings.ts`), what gets touched (`agent_servers["omp-acp"]`), how to extend (`MANAGED_ZED_KEYS` + `buildManagedZedSettings`).
  - One-line C# split note: `Zed → Roslyn for IDE, OMP → csharp-ls for headless. See README.md#zed-integration for the trade-offs.`
- Move the OmniSharp contingency, Razor disclaimer, and Bun.which rationale to the README (which already partially has them).

#### M12 — "Env contract" table cell `OMP_AGENT_DIR`

- **File:** `AGENTS.md:91`
- **Wrong:** `$PI_CODING_AGENT_DIR or ~/.omp/agent` — capital-Pi-Coding-Agent-Dir is correct (Pi-era env name) but a fresh reader has no idea why. The whole table is 4 vars consumed by plannotator's standalone CLI; that's narrow utility.
- **Fix:** Keep the table (it pays rent — those vars are referenced by the deployed extension). One-line context above: `Set by the superpowers-bootstrap extension's session_start handler for subprocesses that need to resolve OMP internal URIs without bash-tool expansion.` (Already there at line 84 — the wording is fine. M12 is a non-issue on re-read; downgrade to no-op.)

## `agent/AGENTS.md` (deployed, 23 lines) — `skill://writing-agent-instructions`

### Strengths

- 23 lines — exceptionally tight. ✓ skill: "target under 100 lines."
- States its provenance in line 3 ("Source-of-truth: glockyco/omp-agent-setup/agent/AGENTS.md").
- Recovery diagnostics at the bottom.

### Issues

#### I13 — "Editor surface: Zed (ACP)" section is the largest section

- **File:** `agent/AGENTS.md:13-19`
- **Wrong:** 2 paragraphs (~120 words) in a 23-line file. That's 35% of the document. Most of it is ACP protocol surface enumeration (`fs/read_text_file`, `terminal/*`, `session/request_permission`) and C# split rationale.
  - For an agent running inside Zed via OMP-ACP, the operational facts are: (1) read/write touch Zed's buffers and save pipeline; (2) destructive tools prompt for permission; (3) LSP/DAP/subagents stay in OMP. The protocol method names don't matter to the agent itself.
  - The C# rationale (last sentence of paragraph 2) is editor-config, not agent-operational.
- **Skill:** "Every line must pay rent by preventing a real mistake or making necessary commands and constraints cheap to find."
- **Fix:** Reduce to ~3 sentences: "OMP runs inside Zed via ACP. `read`/`write` work against Zed's buffers (unsaved changes are visible), `bash` opens Zed terminals, destructive tools (`edit`, `ast_edit`, `write`, `bash`) gate via permission prompts with "allow always". LSP, DAP, and subagents stay in OMP." Drop the protocol method names and the C# parity sentence.

#### C14 — Conventions paragraph omits `~/.config/zed/settings.json`

- **File:** `agent/AGENTS.md:21`
- **Wrong:** The "Files under `~/.omp/agent/` are owned by `glockyco/omp-agent-setup`" enumeration covers AGENTS.md, extensions, lsp.json, skills, config.yml — but does NOT mention `~/.config/zed/settings.json`. A subagent (or human) seeing bootstrap touch settings.json now has no guidance that this is owned. Stale relative to the Zed managed surface we just added.
- **Fix:** Append to the existing sentence: `... managed keys in config.yml, and managed entries in ~/.config/zed/settings.json (specifically agent_servers["omp-acp"]) are owned by glockyco/omp-agent-setup. Don't edit those parts directly.`
